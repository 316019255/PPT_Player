# PPT Player

带账号体系的在线 PPT 编辑 / 放映工具：浏览器里做演示文稿、全屏放映，也能导入 `.pptx`。
数据存在 Postgres（Supabase，连接串 `DATABASE_URL`，表结构见 `db/schema.sql`）。
`.pptx` 的解析和图片抽取全在浏览器里完成，服务器不收文件字节；抽出来的图片按导入时的勾选进
Supabase Storage（换设备也看得到）或本机 IndexedDB（只在当前浏览器有效），deck 里只留引用。

技术栈：Next.js 16 App Router + React 19 + Tailwind v4 + zustand + pg（node-postgres），
登录态是 `httpOnly` 的 JWT cookie。除一个 Postgres 外没有别的必选外部服务；
要用「☁️ 云端」素材（以及导入 `.pptx` 时默认的传云端）才需要再加一个 Supabase Storage 桶。

## 本地开发

```bash
npm install
cp .env.example .env.local   # 填 DATABASE_URL；开发环境 JWT_SECRET 可以留空
npm run db:push              # 把 db/schema.sql 应用到这个库（幂等，可重复跑）
npm run dev
```

开发环境下如果没有配 `JWT_SECRET`，会自动生成一把随机密钥写进 `data/.jwt-dev-secret`（权限 0600），
不需要手工处理。

常用命令：

```bash
npm run db:push     # 应用 db/schema.sql
npm run media:setup # 建/刷新云端素材桶，并打印要填的环境变量
npm run media:setup -- --verify # 只跑云端实测清单（签名上传、公开读、去重、拒收非位图…）
npm run lint        # ESLint，应为 0 problems
npm run typecheck   # tsc --noEmit
npm run test        # node --test，覆盖导入/校验/缩放等纯逻辑
npm run build && npm start
```

## 点开一页为什么要等（实测，别重新推导）

站点的每次页面跳转都是服务端渲染，都要连一次东京的 Supabase（`aws-0-ap-northeast-1`）。实测基线：

| 项目 | 数字 |
| --- | --- |
| 一条查询的往返 | 稳定 177–196ms |
| 新建一条连接（TCP + TLS + 认证） | 1291–3930ms |
| 这台机器到库的下行吞吐 | **20–45 KB/s** |
| 读回 deck 11 的 162KB JSON | 2975 / 4088 / 7486ms |

由此得出的四条已修掉：

- **串行查询改并行**：列表页原来 4 跳（用户 → decks → 又一个 COUNT → 分类），编辑器 3 跳。
  互不依赖的现在用 `Promise.all` 一起发；那个多余的 COUNT 直接删掉（decks 已经全在手里了）。
- **列表页不再为数页数拖全量 JSON**：页数由 `db/schema.sql` 里的 `slide_count()` 在库里算。
  同一份数据实测：`SELECT ... data ...` 728ms vs `SELECT slide_count(data) ...` 95ms。
- **连接池不再掐空闲连接**：原来 `idleTimeoutMillis: 10_000`，只要在一页上停留超过 10 秒，
  下一次点击就要重付 1.3–3.9 秒的握手。现在 5 分钟 + TCP keepalive。
- **加了骨架屏**：`dashboard` / `editor/[id]` / `play/[id]` 各有 `loading.tsx`。
  没有它时点击后整页不动，看着像卡死。

改后实测（dev:3000，探针账号，名下一份 35KB + 一份 2.4KB 的 deck）：
`/dashboard` 0.21s（改前 0.75–0.84s）、`/editor/17` 0.30s、`/play/17` 0.27s、`/api/presentations` 0.16–0.19s；
**空闲 13 秒后再点仍然是 0.21s**（改前在这里要多付一次重连）。

还剩一条改不掉的：**本地打开一份大 deck 依旧要等它从东京回到这台机器**——deck 是整份存在一行 `data` 里的，
162KB 走 40KB/s 的链路就是 3–10 秒。上线 Vercel 后这段变成 Vercel↔Supabase 的机房内网，基本消失；
浏览器侧也不是瓶颈（`/editor/17` 整个 HTML gzip 后只有 9–10KB，传输带 `Content-Encoding: gzip`）。
真要根治就得按页取数据（拆成每页一行或 `?slide=N` 局部接口），那是模型级改动。

顺带一句：本地开发时左下角那个圆形浮标是 Next 开发模式的角标（DOM 里的 `<nextjs-portal>`），
不是页面内容，生产构建没有它；`next.config.ts` 里已经用 `devIndicators: false` 关掉。

## 自动保存与本机草稿

一次改动 = 一趟东京往返 + 整份 JSON 重传，所以存盘尽量攒着发。规则都在 `src/lib/autosave.ts`（纯函数，可单测）：

| 情形 | 行为 |
| --- | --- |
| 停下来不打字 | 攒够 **8 秒**空闲再 PUT（每动一下就重新计时） |
| 一直打下去 | 最迟 **30 秒**强制 flush 一次，躲不掉 |
| 存盘失败 | 重来第 1 次退 **16 秒**，之后一律 **30 秒**封顶（32/64 那两档被上限截住）；连失 3 次停手并亮错误 |
| 内容没变（`dirty` 为 false） | 一次请求都不发，点保存只会显示「✓ 已是最新」 |
| 切后台 / 关标签页 | 立刻 flush 本机日志并尝试补一次 PUT |
| 打字途中 | 每 400ms 防抖把当前内容写进 IndexedDB `ppt-player-drafts` |

本机日志独立开一个库（不动素材那个 v3 库的版本号，免得把 live 连接全踢掉）。下次进来只做一件事：
**比内容**（不比时间戳——线上的 `updated_at` 前端拿不到，跨设备时钟更不可信），本机这份更新才在画布下方
亮一条蓝栏「本机存着一份和线上不一样的草稿…」，点「恢复这份」才推上线，点「丢弃」就删掉。加载页面本身不弹东西。

实测（同一份 2 页探针稿，dev:3000 与 prod:3113 各跑一遍，20 项断言全过）：
打字后 6.5 秒 **0 次请求**，第 **8.0 秒**恰好 1 次 PUT；每 2 秒敲一次连敲 34 秒，全程只有 **1 次** PUT，
落在第 **30.0 秒**；`Page.crash` 真崩（不走 beforeunload）时本机已有那一笔且上传 0 次，重进 **0.7–1.1 秒**
出蓝栏，点恢复后 0.2–1.3 秒线上就变成崩溃前那份。

两条取舍，说明白：

- **PUT 没有版本号**：两台设备同时开同一份，后保存的那份整份覆盖前者（本来就是整份存的模型）。
- **`未命名新建`那把钥匙按浏览器存**，不认账号：公共电脑上下一个人打开新建页，会被问要不要恢复上一位的草稿。
  要收紧就把用户 id 拼进 key（`new:{userId}`），代价是 `EditorClient` 得多一个 prop。

## 上公网前的清单

1. **`JWT_SECRET` 必须显式配置**，至少 32 字符：
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   生产环境缺这把钥匙时，签发和校验登录态都会直接失败（fail closed），不会退回某个默认值。
2. **必须走 HTTPS**。生产下 cookie 带 `Secure`，用 http 访问会登录不上——这是有意的。
3. **`ENABLE_DEV_PRO_GRANT` 保持 0**。目前没有接支付，生产默认关掉「自助升级 Pro」接口，
   否则任何人都能把自己变成 Pro，配额就形同虚设。要给自己开 Pro，直接改库：
   ```sql
   UPDATE users SET pro = 1, pro_expires_at = now() + INTERVAL '365 day' WHERE email = 'you@example.com';
   ```
4. **`DATABASE_URL` 只在服务端用**。填 Vercel/环境变量的值不要加 `NEXT_PUBLIC_` 前缀，带前缀会被打进浏览器包。
   - 用 Supabase 的 **pooled 连接串（端口 6543）**：Serverless 下每个实例各自建池，池子大小限 3，走事务池才不会把连接数打满。
   - pooler 的证书出自 Supabase 自建 CA（`Supabase Root 2021 CA`），不在系统信任库里。默认只加密、不验证链；
     要完整校验，把根证书 PEM 原文放进 `DATABASE_CA_CERT`，应用会自动改成 verify 模式。
   - 应用连的是表主角色，Postgres 里表主绕过 RLS，所以**不要指望 RLS 兜底**：
     每条读写都带 `user_id` 条件，这是唯一的隔离层，改路由时别把它写丢。
5. **`public/uploads/` 已不再有新写入**（`.gitignore` 已排除，不要进版本库）。导入搬进浏览器之后，这里只剩
   旧服务端导入留下的历史素材，`/uploads/[name]` 这条只读路由专供它们。自托管若要让旧 deck 的背景继续显示，
   就把这个目录一起持久化；Vercel 上它本来就不存在，引用它的旧幻灯片会按「缺素材」降级。
   `data/` 现在只剩开发用的 JWT 密钥。
6. **反向代理放开请求体上限到 4MB 左右**（nginx：`client_max_body_size 4m;`）——`.pptx` 的字节不再进服务器，
   最大的请求体是一份 deck JSON（服务端限 2MB）。仍然不要缓存 `/api/*`；透传 `Cookie` 即可，应用不做服务端 session。
7. **部署新代码前先在目标库跑一次 `npm run db:push`**。列表页和 `GET /api/presentations` 现在都调用
   `db/schema.sql` 里的 `slide_count()` 函数（页数在库里数，不再把整份 deck JSON 拖回应用），
   那个函数还没建就部署的话，这两个读会直接报错。
8. **`ADMIN_EMAILS` 填真实注册过的邮箱**（逗号分隔），后台 `/admin` 才对谁开放。留空是「后台整个关着」：
   页面退回 `/dashboard`，接口未登录 `401`、登录了但不在名单里 `403`，没有兜底通道。名单每次请求现读，
   不区分大小写；游客的合成邮箱（`guest_xxx@ppt-player.local`）即使误填进去也不放行。
   第一个管理员账号用 `npm run admin:set <email> <password> [名称] [--reset]` 建（已存在的邮箱要 `--reset`
   才动密码，且它不会顺手改掉原名称）—— 注册页卡「密码至少 8 位」，短密码或临时测试号只能走这条。
   「现读」指的是不用改代码，但 env 只在进程启动时读进来：改完 `.env.local` 或部署平台的变量要重启才生效。

## 配额与硬限制

除「导入 `.pptx` 的体积」之外，这些都在服务端写入口拦，不是只有前端提示——
`.pptx` 的字节不进服务器，体积只能在浏览器里判，服务端拦的是它最终存下来的那份 deck：

| 项目 | 上限 |
| --- | --- |
| 免费版演示文稿数 | 1 个（Pro 不限） |
| 单个演示文稿 | 500 页 / 每页 100 个元素（文字块 + 图片块合并计数）/ 序列化后 2MB |
| 单个文字块文本 | 5000 字符 |
| 本地素材单文件 | 200MB，仅常见图片与视频类型（存浏览器 IndexedDB，不进服务器） |
| 云端素材单文件 | 12MB，仅位图（png/jpg/webp/gif/bmp/avif）；由桶配置和服务端签发路由两处各挡一次 |
| 导入 `.pptx` | 200MB，最多取前 500 页（在浏览器里解压解析；超页的部分会被丢掉并写进告警） |

安全相关的既定策略：

- 导入 `.pptx` 必须登录（浏览器解析完，仍要过 `POST /api/presentations` 的登录态与配额）；抽出来的图片按内容
  sha256 命名，包里的部件路径只承认 `ppt/media/` 下一层（`../` 、子目录、非媒体部件一律读不到），
  任何一张图存失败只影响那一张（写进告警、这张降级），不会让整份导入半途而废。
- `image/svg+xml`、`text/html` 不在允许类型内——它们会从站点自身源执行脚本。
- 读取时用 `parseSlides` 把库里的任意 JSON 收敛成合法结构，越界数字、非法颜色、超长文本都会被修正。
- 图片/视频背景的地址只承认 `https://…` 或站内绝对路径（`/uploads/…`）；
  `data:`、`//evil.com`、Windows 路径这类会被丢掉并降级为无背景——这些值最终会拼进 CSS 的 `url()` 和 `<video src>`。
- 「本地素材」背景写成 `local:<key>`：key 只接受 UUID 形状（无 `/ \ . : 空格 引号`），从不被当作 URL 使用；
  真正进 CSS/`<video src>` 的是浏览器 `URL.createObjectURL` 出来的同源 `blob:`，deck JSON 左右不了它。
- 云端块只承认 `u{userId}/{64 位小写 sha256}.{位图后缀}` 这一种形状，后缀逐个列出来（不放 `[a-z]{3,4}`，
  否则 `.svg`、`.txt` 也会通过）；域名由 `NEXT_PUBLIC_MEDIA_PUBLIC_BASE` 在浏览器里拼，两者任一段不合形状就返回空串，
  按「缺素材」降级，绝不拼半截 URL 去请求。deck 里存的键和桶里的键是同一个字符串，因为出自同一个构造函数、又立刻回头过一遍校验。
- 上传地址只由 `/api/media/sign` 在登录态里签发：用户 id 取自 session（请求体里传 `userId` 无效），
  后缀由 MIME 反推（不接受前端传来的后缀），按内容 sha256 命名，所以重复上传同一张图不会多占空间。
- 每份数据的读写都带 `user_id` 条件，分类同理。

## `.pptx` 导入能做到哪一步

导入全程在浏览器里完成：解压、读 OOXML、抽图、存图，最后只把这份 deck 的 JSON 交给服务端。
导入的内容包括文字、纯色背景、**图片背景**和**正文图片**：坐标、字号、颜色、粗斜体、对齐都从 OOXML 直接读，
分组里的形状会按组的缩放比例换算回页面坐标；`a:srcRect` 的裁切按 `cover` 处理，`a:tile` 平铺按原样平铺。
正文里的 `p:pic` 会变成可继续拖拽、改层级的图片块，按原位置原大小摆在画布上；
一页最底层、覆盖 80% 以上画面的图片会被认成该页的背景。
抽出来的图片按界面上「导入的图片传上云端」的勾选落位：默认传 Supabase Storage（换设备也看得到），
取消勾选就只进这台电脑这个浏览器的 IndexedDB。

以下会被跳过或降级，导入后编辑器顶部会列出跳过了什么：

- 视频、图表等非位图媒体（按类型计数告警）
- 浏览器画不出来的图片格式（emf/wmf/tif/svg 之类）——连字节都不读，直接告警
- 带旋转或翻转的图片（按水平摆放，会告警）
- 母版 / 版式里的文字（页面上没有的文字不会凭空出现）
- 继承自版式的字号（按块高兜底一个值，需要手动微调）
- 超过 500 页时只取前 500 页

放映页与编辑器共用同一套舞台渲染：内容按 1280×720 的设计尺寸排版，再整体等比缩放，
所以投屏、笔记本、手机上字号和位置的比例关系一致。

## 还没做的

- 分享链接 / 公开放映页：所有页面（含 `/play/[id]`）都要求登录，只能自己看。
- 转场动画、自动播放、演讲者备注。
- 支付通道（Pro 只有标记位和过期时间）。
- 视频作为可摆放位置的内容块（图片已经可以：本机 / 云端 / 网络地址三种来源，视频仍只能作背景）。

## 手机端

**全站只有一个判定**：`useCompactEditor` 读 `(max-width: 767px), (max-height: 559px)`——
**窄或者矮**都算手机。加「矮」这一条是因为横屏手机（约 844×390）宽度已经过了 767，只看宽度会给它一套桌面布局，
而横屏正是主战场。编辑器、列表页 `/dashboard`、放映页 `/play/[id]` 都读它，CSS 变体和 JS 判断共用同一个断点，
免得各认各的。服务端没有视口，首帧一律按桌面渲染，hydration 时立刻换成真实结果。

编辑器的手机布局是两层：**紧贴标题栏、按宽度铺满的大画布**，加上**一整块贴底的「坞条 + 编辑窗」**。
这块叠层不跟画布抢高度：放得下就接在画布底下（零重叠，看上去仍是上下两层），放不下就往上顶、盖住画布底部那一条。
宁可被盖住下半截，也不能让画布缩——窗里改一个字、拉一根滑杆，画布露在上半截的那部分就是实时预览。
四个键一直在、一眼能看见能按到，键上那行小字就是当前页的读数（第几页、几行字、几张图、什么背景）；
**「📄 页面」排在第一个，进编辑器就默认展开它**。一次只开一个窗，点着亮的键就收起。

| 键 | 编辑窗里能做什么 |
| --- | --- |
| 📄 页面 | 新增一页（直接进文字输入态）、复制本页、删除本页、两列缩略图点谁切谁（一屏看得见六到八页） |
| ✏️ 文字 | 打字改文字、字号 10–144、8 个预设色 + 自选、左中右、粗体斜体、层级（最后/↓/↑/最前）、宽/高/不透明度三根并排滑杆、复制这一行、删除这一行、加一行 |
| 🖼️ 图片 | 插一张（本机 / 云端 / 网络地址，与电脑端同一个选择器）、显示方式（完整/填满/拉伸）、层级、宽/高并排滑杆、☁️ 存到云端、删除这张 |
| 🎨 背景 | 整页背景：🖼️ 图片 / 🎬 视频 / 📁 本地 三个 tab，与电脑端同一个选择器。素材格子**一排 2 个竖向排、跟着窗往下滚**（电脑端仍是那一条单行横滚） |

叠层高度是算出来的，不是挤出来的：`max(min(下限, 键盘以上的空间), 键盘以上的空间 − 画布底边)`。
画布按宽度定死 16:9、永远满尺度；键盘那一截写在叠层的 `bottom` 上，不能写 `main` 的 `paddingBottom`
（绝对定位的包含块是 padding box，那样叠层不跟着抬、高度还会把键盘重复算一次）。按 356×768 这套算式：
不弹键盘时叠层顶边正好等于画布底边（零重叠，舞台 356×200）；弹 300 高的键盘时舞台**仍是 356×200**
（改之前这里会缩成 331×186），叠层往上盖住画布底部 28px；空间连下限（坞条 + 窗 170px）都不够时封顶在画布区
顶边、改由窗内滚。不弹键盘时文字 / 图片 / 页面三个窗 `scrollHeight == clientHeight`，全套控件一屏放完；
背景窗装的是素材列表，两列竖向往下滚着看（滚近才挂图，一屏几十张原图同时解码会把浏览器打趴）。按 ✕ 收起后叠层只剩坞条
那一条，坞条位置一动不动。横屏走画布右侧一栏（42% 宽，240–320px），键照样排在编辑窗上面。

**撤销**：标题栏「💾 保存」左边的 `↶`（电脑端写作「↶ 撤销」），按一次退回上一步，正看着哪一页、选着哪一行
也一起退回去；没得撤时按钮灰着但一直摆在那儿。历史记在 store 里（`src/lib/history.ts` + `pptStore` 的 `past`），
电脑端和手机端撤的是同一份，最多留 60 步，换 deck 或导入时清空（撤不出上一份 PPT 的内容）。
**一次连续动作算一步**：打字、拖角、拖滑杆、拖取色器在 1 秒内的一串改动合成一步，撤一次整串都没了；
点粗体、改对齐、换背景、删一行这种点一次的事各算一步。撤完紧接着再改会另起一步，不会和被撤掉的那一串粘回去。
没有重做，也没有 Ctrl+Z —— 那会和输入框自带的撤销打架。

三处不显眼但决定能不能用的处理：

- **打字走编辑窗里的 `<textarea>`**，不在缩放后的舞台上做 contentEditable：舞台在手机上只有约 0.3 倍缩放，
  光标和选区对不准；`<textarea>` 用 16px 字号，免得 iOS 一聚焦就把整页放大。键盘高度由 `visualViewport`
  量出来，作为叠层抬起的距离；横屏弹键盘**不**退回叠式（横屏可用高只有约 390，叠式要给画布留的最低高度一钳
  就钳成 0 高、画布整个空白），让步的是右栏自己的高度。
- **改大小走画布外层的 4 个角手柄**：它们挂在 `transform: scale()` 之外，所以永远是指头大小（44px 热区、
  20px 方框），不会跟着舞台缩没。块贴着舞台边时手柄会被屏幕沿切掉，所以宽/高还各有一根滑杆兜底。
  手柄与滑杆共用 `src/lib/block-geometry.ts` 里同一套换算与钳位，`tests/block-geometry.test.mjs` 有一条
  「滑杆结果 ≡ 手柄结果」的等价测试，两边不可能各跑各的。键盘弹起、叠层盖住画布底部那一条时，
  块最下面那排手柄跟着被盖住（手柄层不画到窗之上）——改大小走窗里那两根滑杆，按 ✕ 或再点一次亮键就全露出来。
- **删除类都是「按一次 → 再确认一次」**，不用系统 `confirm`（部分安卓浏览器会静默记住它的选择，等于没确认）。
  确认态 4 秒自动取消、按到别处也取消，换到另一行 / 另一页时按钮整个复位——不会出现「刚才武装的是 A，
  一按删了 B」。

仍只在电脑端：改标题、文本框的圆角 / 内边距 / 边框 / 框内背景、8 手柄里的四个边中点（手机上只给 4 个角）、
pptx 导入（下面列表页那节写了为什么）。

### 列表页 `/dashboard`

手机端换成**顶栏 + 一行分类 chips + 单列卡片**，整页竖向滚。不用「固定高度 + 区内滚动」那一套：
桌面那 224px 的左侧栏在手机上不许缩，主区只剩 132px，卡片里的两个键各剩约 10px，谁也按不到。

- 左侧栏整个不渲染。新建在顶栏右边，分类管理是 chips 末尾那个「＋ 分类」，升级 Pro / 退出登录在 ☰ 账户窗里；
  两个窗都是贴底抽屉，点背板或 ✕ 关闭，里面的输入框一律 16px（iOS 上小于 16px 会一聚焦就把整页放大）。
- **导入 `.pptx` 和「☁️ 云端保存」勾选框在手机上彻底不出现**，不是灰着不给按：导入要在浏览器里解 zip、
  几十次图片解码，手机上慢且容易被系统中途杀掉进程；一个按下去不动的键比没有这个键更坏。
- 卡片三个键并排 `✏️ 编辑` / `▶ 播放` / `🗑 删除`，删除走两次点击；桌面卡片仍是编辑 / 播放两个键，
  删除在 `⋯` 菜单里走系统 `confirm`（弹层里塞不进一个常驻的两次点击键）。
- 报错、超配额、升级成功都是页面里的**提示条**（手动「知道了」关闭），不再用 `alert()`：
  系统弹窗点掉就不留痕迹，回头看不出那条错误讲的是哪一个演示文稿。配额那条也折进同一个位置，不会两条黄条叠着。

### 放映页 `/play/[id]`

纯手指就能翻页：**点屏幕左 / 右半区**上 / 下一页，或者**左右滑动**。判定在 `src/lib/play-gesture.ts`：
横向位移 ≥40px 且横向不小于纵向才算翻页，斜着往下拖当成上下滚动、不抢。
划动之后浏览器还会补一个合成 click，靠 400ms 时间戳隔掉——用时间戳而不是布尔标志，
是因为各家浏览器 `preventDefault` 能不能吃掉那个 click 并不一致。手势层写了 `touch-action: none`，
免得横向划动被浏览器拿去滚动或双击缩放；这一层必须自己接 `onTouchStart/onTouchEnd`，
`SlideStage` 只往外转发 `onClick`，touch 事件塞给它会静默丢掉。
桌面窗口态一点没变：仍然只有进全屏后点屏幕才翻页，键盘 / 翻页笔 / 蓝牙遥控器照旧。

- 顶栏手机上只留 `← 返回`、会截断的标题、`⋯`（编辑此叠 / 遥控器说明 / 退出放映）和 `⛶ 全屏`；
  桌面那四个键并排约 406px，356px 的屏上最右边的「⛶ 全屏放映」会被整颗挤出屏幕外。
- 底部那条圆点进度条手机上不渲染（29 页的歌稿＝29 个 8px 的点，整条约 600px，两头被切、一个也按不到），
  换成 `⏮ ◀ 3 / 29 ▶ ⏭`，页码本身是个键，点开是 44px 一格、能内部滚动的数字跳页层——
  「直接跳到第 17 段副歌」的手指版。
- **浏览器不支持全屏时，`⛶ 全屏` 和居中大 `▶` 都不出现**，并留一条提示「此浏览器不支持整屏放映，
  已用窗口放映；点屏幕左右或左右滑动就能翻页」。iPhone Safari 对普通元素不开放 `requestFullscreen`，
  按下去没反应的控件等于没有；那个居中大 `▶` 本来就调 `enterFullscreen`，还占住舞台正中一块翻页区域，
  手机端顶栏已有 `⛶`，所以它也不出现。有些浏览器（iOS 16.4+）会把方法暴露出来却又当场拒绝、
  连 promise 都不 reject，所以请求完还要回读 `document.fullscreenElement` 才敢说真进了全屏。
- 键盘快捷键那行提示只在桌面渲染（手机上没有键盘），并加了 `pointer-events-none`——它压在底部中央，
  本来会吃掉那一片的翻页点击。

其余页面（`/`、`/login`、`/register`）没有硬伤，只把高度单位从 `vh` 换成 `dvh`：
`100vh` 按 iOS 收起工具栏之前的视口算，比真实可视区高出一截，会把底部内容压到浏览器条底下。
首页那两个 CTA 并排需要约 344px、可用只有 308px，改成窄屏竖排、≥640px 回并排。

## 「📁 本地」素材（浏览器本机，不上传）

编辑器画布**下方那条背景栏**里的「📁 本地」标签页选的是**你自己电脑上的图片/视频**，直接读本地文件做背景：
文件字节存进浏览器的 IndexedDB，deck 里只保存一个 `local:<key>` 引用，不上传服务器，放映时直接读本机，速度快。

- 只在**添加它的那台设备的那个浏览器**里有效。换浏览器、换设备，或换一个网址打开
  （`localhost:3000`、`127.0.0.1:3000`、正式域名是不同的存储分区）时，本地背景退化成纯色，不报错、也不发任何请求。
- 部署上线后需要在**那个正式网址下重新选一次**素材。
- 素材占用的是本机浏览器存储（那一行右侧显示「共 N 项 · X MB」），只有在该标签页里手动 🗑 才删除；
  删 deck 或换背景不会自动回收，需要时手动清理。
- 🗑 删除前会弹确认：文件只在这台设备的浏览器里，删掉找不回。

### 「📁 选择素材文件夹」批量导入

同一个标签页里可以指定**一个本机文件夹**，之后把图片/视频丢进这个文件夹，扫描一次就自动补进素材库，
不用逐个点「选择本机文件」。

- 依赖 `showDirectoryPicker`，**只有 Chrome / Edge 有**；不支持的浏览器上这个按钮不出现，
  页面会写一行说明，「＋ 选择本机文件」照常可用。
- 文件夹句柄存进 IndexedDB，但**浏览器在每次重新打开网页后都会忘记授权**，按钮会变成
  「🔓 重新授权」，点一次才能继续扫描；没拿到权限时扫描直接失败报错，不会静扫。
- 扫描是增量的：按「名字 + 体积 + MIME」和本地库比对，已有的项**不解码、不重复写入**，
  只有新文件才生成一次预览（串行处理，一次只解一个原图）。
- 只扫这个文件夹**本身这一层**，不进子文件夹；`.` 开头的文件（`.DS_Store` 等）跳过。
- 扫描是把文件**复制进 IndexedDB**，之后放映不再依赖那个文件夹（也不需要授权）。
- 从文件夹扫进来的素材被 🗑 删掉后，**下次扫描会重新出现，但会是新的 `local:<key>`**——
  正在用它做背景的幻灯片会变回纯色。确认框里会提前说明这一点；不想它回来就别再放进这个文件夹。

`.pptx` 导入抽出来的图片走的也正是上面这两条路：默认传「☁️ 云端」，取消勾选、云端某一张没存进去、
或者根本没配 `NEXT_PUBLIC_MEDIA_PUBLIC_BASE` 时退到「📁 本地」，界面会把属于哪一种写清楚。
导入不再要求服务器有可写的盘，Vercel 这类无盘部署也能整份导入成功。

## 「☁️ 云端」素材（传到站点自己的对象存储）

「插图片」那条里的「☁️ 云端」把图片传进站点的 Supabase Storage 桶。deck 里只存桶内路径
`u{你的用户id}/{图片内容 sha256}.{后缀}`，**不存域名**，域名在浏览器里由环境变量拼出来。
所以换电脑、换浏览器、换一个网址打开，图都还在——这正是「📁 本地」做不到的那一段。

一次性配置（需要 `SUPABASE_URL` + `SUPABASE_SECRET_KEY`）：

```bash
npm run media:setup
```

它会建好（或刷新）桶 `slide-media`：公开读 · 单文件 ≤12MB · 只收位图，然后打印要填进
`.env.local` 和 Vercel 环境变量的两行：`SUPABASE_MEDIA_BUCKET` 和 `NEXT_PUBLIC_MEDIA_PUBLIC_BASE`。
第二行不是密钥，本来就是要给浏览器用的；只有带 `NEXT_PUBLIC_` 前缀的这一个能进前端包。
配好后 `npm run media:setup -- --verify` 能把那 8 条实测假设再跑一遍。

为什么长成这样：

- **字节不经过我们的 API**。服务端只签一个一次性上传地址，浏览器直接 PUT 进桶。
  Vercel 的 Serverless 请求体约 4.5MB 上限、也没有可写的盘，转发字节这条路走不通。
- **签发必须在我们自己的登录态路由**（`/api/media/sign`）。Supabase 的公开 key 签不出上传地址
  （RLS 直接拒），所以浏览器里既不需要、也拿不到任何密钥；token 只对那一个 key 有效、且默认不许覆盖写。
- **按内容命名**：同一张图第二次上传，在签发阶段就报「已存在」，界面写「云端已经有同一张」，一个字节都不再传。

界面上的规矩：

- 没配 `NEXT_PUBLIC_MEDIA_PUBLIC_BASE` 时，「☁️ 云端」的上传按钮是**灰的，并在状态行写清原因**，
  不会让你点出一个必然失败的上传；已经存在的云端块退化成「云端图片地址未配置」的空框，而不是「图丢了」。
- 「📂 导入 .pptx」按钮下方常驻一个「导入的图片传上云端（换设备也看得到）」勾选框，默认勾上；
  云端地址没配时它是禁用态并就地写明原因。导入过程中按钮上是分阶段进度（解析中… / 传图 n/m / 整理中… / 保存中…），
  走完直接进编辑器。告警会区分开两种情况：「N 张图片云端没存进去，已改存本机素材库」和
  「按「不传云端」导入：N 张图片只存在这台电脑的这个浏览器里」——前者是回退，后者是本来的选择。
- 选中一张来自「📁 本机」的图片块时，右侧有「☁️ 存到云端（换设备也看得到）」：
  从这台设备的 IndexedDB 取出字节传上云，成功后就地改成云端引用。
  本机没有这份字节时（换新电脑就是这个情况）明确报错并**保持原来的引用不动**，不会把数据改坏。
  这是一张一张搬的，没有「整本一键全搬」。

要知道的代价：

- **没有按用户配额**：登录用户能一直往桶里传；删 deck、换图、改成云端引用都**不会**回收桶里的旧对象（孤儿文件）。
  要控成本就得补配额 + 清理任务，否则就接受这份存储费。
- 放映时观众的设备需要能访问那个 `*.supabase.co` 域名；断网/内网放映请用「📁 本地」。
- 桶是**公开读**：拿到完整路径的人就能看到那张图。路径是 sha256、目录列不出来，但这不算隐私隔离——
  真正私密的内容别放云端。

## 后台管理（`/admin`）

权限只有一条来源：`ADMIN_EMAILS` 里的邮箱。判定在 `src/lib/admin.ts`，页面用 `getAdminUser()`
（不是管理员就 `redirect('/dashboard')`），接口用 `requireAdmin()`——未登录 `401`，
登录了但不在名单里 `403`。名单为空时一律拒绝，`/api/admin/*` 没有任何兜底通道。

入口在 `/dashboard`：桌面端在左侧栏底部「退出登录」上方，手机端在 ☰ 的账户窗里。
**非管理员这两处都不渲染**（不是 `opacity-0`、不是隐藏），所以访客看不到也点不到。

页面与接口：

| 后台页 | 接口 | 现在能做什么 |
| --- | --- | --- |
| `/admin/materials` | `GET/POST/PATCH/DELETE /api/admin/materials`、`GET /api/admin/materials/categories`、`GET /api/admin/materials/refs`、`POST /api/admin/media/sign` | 在线素材的唯一真相（编辑器那面「在线」格子就是这张表）。支持浏览器直传 Supabase 桶（`lib/{sha256}{ext}`，重复传不占第二份空间）与粘外链；改标题/分类/排序、上线·下线；删除默认只下线，真删桶内文件要二阶确认且只允许 `lib/` 前缀，删之前先报「几份稿子在引用它」 |
| `/admin/users` | `GET/PATCH /api/admin/users` | 按 会员·普通·游客 筛选（默认档排除游客）、按邮箱/姓名搜索、分页；每人显示自己的 PPT 数量。授权是意图式的：`grant: 'permanent' \| { days: n } \| 'revoke'`，到期时间一律服务端算，客户端传日期串不再收；游客行没有可登录身份，给它开会员直接 403 |
| `/admin/decks` | `GET /api/admin/decks`、`GET /api/admin/categories?userId=`、`PATCH/DELETE /api/admin/decks/[id]` | 用户自建 PPT 的检索（标题/作者邮箱/姓名）、按作者与分类筛选、分页；每行显示页数与字节（库里 `slide_count()` + `octet_length()`，**列表绝不 SELECT `data`**）、改名（与用户侧同一条规则）、移分类（分类按**这份稿子作者**的目录校验，不是管理员自己的）、删除（只删行，桶内素材保留） |
| `/admin/decks/[id]` | — | 只读预览：复用放映页那个 `PlayerClient`，管理员看不到任何进别人编辑器的入口（不是灰掉，是不渲染） |

三张列表页的首屏数据都由服务端组件查（`src/lib/admin-data.ts` 只管执行，SQL 文本在
`src/lib/admin-sql.ts`，页面与接口共用同一份），客户端只在筛选、增删之后重查，
不再有「挂载即 setState 拉数据」那一层。SQL 文本单独成一份的用意：`tests/admin-sql.test.mjs`
能在没有数据库的情况下检查「语句里的占位符编号」和「参数数组的长度」是不是配得上 ——
这两样对不上时 Postgres 不是返回空结果，而是整条语句报错、接口 500。
